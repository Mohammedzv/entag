EBM PRODUCTION SYSTEM — دليل التشغيل
=====================================

المشروع:
- موقع عربي RTL متجاوب للموبايل والكمبيوتر.
- تسجيل إنتاج يدوي لمراحل التجهيز والتحضير والتجميع.
- خطوط إنتاج بأسماء المشرفين ومستهدف يومي وحساب المتبقي.
- بلاغات صيانة للماكينات وتحديث حالة الفني وقطع الغيار.
- تقارير حسب التاريخ والخط.
- صلاحيات تفصيلية قابلة للتعديل للمستخدمين.

مهم قبل التشغيل:
هذه نسخة مشروع جاهزة للربط، لكنها لا تحتوي على مفاتيح Firebase الخاصة بمصنعك ولا حسابات الموظفين. يجب إكمال الإعدادات التالية أولًا.

1) إنشاء مشروع Firebase جديد مستقل
- افتح https://console.firebase.google.com/
- أنشئ مشروعًا جديدًا باسم مثل ebm-production-system.
- من Project settings > Your apps أضف تطبيق Web.
- إعدادات المشروع مضبوطة بالفعل على مشروع Firebase: tyyt-b1d84.
- تأكد أن Realtime Database موجودة على الرابط https://tyyt-b1d84-default-rtdb.firebaseio.com/.
- لا تستبدل إعدادات firebase.js إلا إذا كنت تريد نقل النظام إلى مشروع Firebase آخر.

2) تفعيل تسجيل الدخول
- افتح Build > Authentication > Get started.
- فعّل Email/Password.
- أنشئ أول مستخدم مسؤول من Authentication > Users > Add user.
- انسخ UID الخاص به.
- افتح Realtime Database ثم استورد database.rules.json من صفحة Rules، ثم اضغط Publish.
- بعد نشر القواعد، أضف سجلًا يدويًا في Realtime Database بهذا المسار:
  users/PASTE_ADMIN_UID_HERE
  واجعل القيمة:
  {
    "uid": "PASTE_ADMIN_UID_HERE",
    "displayName": "مدير النظام",
    "role": "admin",
    "active": true,
    "permissions": {}
  }
  استبدل PASTE_ADMIN_UID_HERE بالـ UID الحقيقي في المكانين.

3) تشغيل الموقع
- لا تفتح index.html بالنقر المزدوج؛ استخدم خادمًا محليًا أو استضف الملفات.
- يمكن رفع الملفات إلى Firebase Hosting أو GitHub Pages (بعد ضبط Firebase).
- لتجربة محلية عبر VS Code استخدم إضافة Live Server.
- افتح الموقع وسجّل دخول المسؤول.
- من المستخدمون والصلاحيات: أنشئ سجل صلاحيات لكل حساب موظف بعد إنشاء حسابه في Authentication.

تنبيه أمني مهم:
التطبيق يحفظ مفاتيح الصلاحيات بصيغة آمنة لقاعدة Firebase مثل production.add => production_add، وتتوافق معها القواعد المرفقة. اختبر الصلاحيات بحسابات مختلفة قبل الاعتماد الفعلي. صلاحيات الوصول إلى سجلات كل خط ما زالت تُفرض داخل الواجهة فقط؛ لو مطلوب عزل صارم على مستوى قاعدة البيانات لكل خط، نضيف قواعد/بنية بيانات مخصصة أو Cloud Functions قبل الاستخدام التشغيلي. لا تفتح قاعدة البيانات للعامة ولا تستخدم قواعد .read/.write = true.

حساب العجز:
العجز في شاشة الخطوط = المستهدف اليومي ناقص إنتاج التجميع المسجل لذلك الخط في التاريخ الحالي، والحد الأدنى صفر.
سجلات كل مرحلة تحفظ كما أدخلها المستخدم؛ يجب تسجيل الكميات وفق آلية المصنع الفعلية لتجنب جمع القطع نفسها أكثر من مرة عبر المراحل.

مجلدات المشروع:
index.html       الواجهة
style.css        التصميم المتجاوب
firebase.js      إعداد الاتصال
app.js           وظائف النظام
database.rules.json  قواعد قاعدة البيانات الابتدائية
README.txt       دليل الإعداد


=== تحديث إدارة المستخدمين (مدير ينشئ مستخدمين) ===
هذه النسخة تضيف إنشاء حسابات المستخدمين من داخل النظام عبر Cloud Functions.

التسلسل:
1. أنشئ أول حساب مدير نظام واحدًا يدويًا في Firebase Authentication، ثم أضف سجل users/UID في Realtime Database كما في خطوات الإعداد أعلاه.
2. المدير الرئيسي يسجل الدخول ويضيف مديرين أو موظفين من صفحة المستخدمين والصلاحيات.
3. المدير الذي يمتلك users_manage يمكنه إنشاء حسابات للموظفين وتحديد صلاحياتهم.
4. المدير العادي لا يستطيع إنشاء مدير نظام أو منح صلاحية لا يمتلكها، ويستطيع إدارة الحسابات التي أنشأها فقط.
5. تعطيل المستخدم من داخل النظام يعطل ملفه في قاعدة البيانات وحساب تسجيل الدخول أيضًا.

نشر الدوال:
- يتطلب Node.js 20 وFirebase CLI، وقد تتطلب Cloud Functions خطة Blaze مع تفعيل الفوترة.
- من مجلد المشروع نفّذ:
  firebase login
  firebase use --add
  cd functions
  npm install
  cd ..
  firebase deploy --only functions,database

ملاحظات:
- ملف firebase.js ما زال يحتاج إعدادات مشروعك الفعلية.
- لا تشارك كلمات المرور مع أشخاص آخرين، ويفضل أن يغيّر الموظف كلمة المرور المؤقتة بعد أول دخول.
- حساب مدير النظام الأول فقط يتم إنشاؤه يدويًا؛ بعد ذلك تتم إضافة الحسابات من واجهة الموقع.
